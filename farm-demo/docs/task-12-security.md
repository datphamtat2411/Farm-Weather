# Task 12 — Security and authorization
Ch.5 §5.4, Table 5.8–5.9; D07 authorization portion. The existing ThingsBoard 4.4.1 non-production image remains the authentication authority. No custom JWT signature algorithm, no changes to platform core. A dedicated farm Customer owns the existing farm/zone and devices. Provisioning uses named native user groups, scoped device/asset/dashboard groups and explicit roles (never built-in read-only role, which includes RPC_CALL and READ_CREDENTIALS). Four distinct named human identities: admin, technician, operator, viewer. Two independent machine identities: reader (only station read/telemetry) and control (station RPC/attributes, alarm acknowledgement and user-group lookup). The latter key must never reach a browser. Raw human RPC and attributes writes are denied even for business admin: the business API is the controlled entry point. Native platform tenant admin is reserved for provisioning, not a daily farm user.
 
The business API verifies JWT using actual ThingsBoard /api/auth/user, then resolves current group membership and station permission. Only the method-specific permissions in Table 5.9 are admitted; no pump-start/clear-alarm method. RPC requests contain a generated command ID and a bounded expiration and remain PENDING until Task 13 implements actual device responses. Config requests are checked for a conservative safe range and do not overwrite the applied configuration. ACK does not clear alarms. Export endpoint returns scoped raw points for Task 15; the viewer is denied this dedicated export endpoint (a person who can read history can still manually copy it). Native account/role management is limited to the farm admin. Native platform audit plus SQLite audit record actor UUID, timestamp, operation, target and outcome; no JWT/password/API key in evidence.

## Reproduce
Use a dedicated non-production instance and the existing Task 10 instructions. Set six distinct FARM_<ROLE>_EMAIL / FARM_<ROLE>_PASSWORD environment variables from a private secret manager, together with FARM_TB_ADMIN_USER/PASSWORD. Run `python farm-demo/cloud/security.py --url https://127.0.0.1:8443 --ca-file /private/ca.crt --output /private/farm-security`. This creates a new private output directory with a manifest and two secret files. Provisioning checks unexpected permissions and ownership and refuses silent privilege drift. Activate new accounts only; never reset existing passwords automatically. If an existing key is lost, revoke/rotate explicitly in ThingsBoard before issuing a replacement. Keep the 30-day service keys outside Git and renew before expiry. Configure Edge FARM_CLOUD_READ_API_KEY from reader.secret and FARM_CLOUD_TOKEN separately from gateway-token.secret. Set FARM_CONTROL_API_KEY from control.secret for `python farm-demo/cloud/farm_api.py --url https://127.0.0.1:8443 --ca-file /private/ca.crt --manifest /private/farm-security/security.json --audit /private/farm-security/audit.sqlite --cert /private/server.crt --key /private/server.key`. Keep native ThingsBoard HTTPS and the farm API loopback-only, use the supplied nginx example for HTTPS/WSS with a trusted domain certificate and verified upstream TLS. MQTT 8883 is a separate TLS connection. Never expose PostgreSQL, the internal broker, or plaintext MQTT. Public hosting, certificate issuance and Task 13 device execution are not performed by CI.

Internal Mosquitto: generate ACL/password configuration with `python farm-demo/edge/mqtt_security.py /private/broker`, using independent random EDGE_MQTT_PASSWORD and SIM_MQTT_PASSWORD (24+ URL-safe chars). Run broker as the owner of that directory on a private interface. Set EDGE_MQTT_USERNAME=farm-edge and SIM_MQTT_USERNAME=farm-simulator; the simulator can publish only its own uplink and read its own downlink, Edge can read app uplinks and publish only mapped station downlinks. The demo simulates the ChirpStack side, not actual OTAA/MIC or RF security. Use real ChirpStack per-device credentials when hardware is deployed. The original anonymous broker config is strictly legacy loopback test-only, not the deployment path.

CI: real native RBAC/REST, TLS negative controls, actual scoped service readback, business API role matrix, revoked group/key, audit records, and actual authenticated Mosquitto integration with denied publishes. Task 17 still requires separate Wokwi hardware acceptance. No claim of production penetration testing or physical radio security.
