# Task 10 — ThingsBoard Cloud integration
Report Ch.5 §5.1–5.3.1, Ch.4 §4.4.2. The repository is unified ThingsBoard 4.4.1-SNAPSHOT. Official 4.4.1 release images are used for reproducible integration (not a build of the fork). Since 4.4, CE and PE are unified. Official NON_PRODUCTION_USE=true enables keyless testing (limited cumulative uptime, visible non-production notice); no license bypass or production deployment claim. See https://thingsboard.io/blog/one-thingsboard-source-available/ and https://thingsboard.io/docs/pe/installation/docker/. Obtain an appropriate license before production.
- Compose: PostgreSQL with persistent volume and private network, SQL time-series, one TB node, MQTT TLS and HTTPS on loopback only, one-year retention. In-memory queue is for PoC; durable Edge verification remains mandatory. Public HTTPS reverse proxy and production credentials/roles belong to Task 12; no public hosting here.
- REST provisioning: idempotent named Farm and Zone assets, station and Gateway devices, profiles, relationships and initial server/shared attributes. No direct SQL mutation. No fabricated client-side applied state. Existing incompatible topology fails; existing user config is preserved. Gateway token is separate from REST credentials.
- Reproduce in a cloud shell/runner: set FARM_DB_PASSWORD, FARM_TLS_DIR (trusted cert/key in server.crt/server.key; ci-tls.sh only for disposable CI), run docker compose -f farm-demo/cloud/compose.yml run --rm -e INSTALL_TB=true -e LOAD_DEMO=true thingsboard on a fresh test DB, then docker compose -f farm-demo/cloud/compose.yml up -d. Do not use demo accounts on a public instance.
- Provision with FARM_TB_ADMIN_USER and FARM_TB_ADMIN_PASSWORD in environment: python farm-demo/cloud/provision.py --url https://127.0.0.1:8443 --ca-file "$FARM_TLS_DIR/ca.crt" --devices-output devices-cloud.json --gateway-token-output gateway-token.secret. Keep generated credentials outside the repository. Set FARM_CLOUD_TOKEN to gateway token and FARM_CLOUD_READ_API_KEY (preferred) or FARM_CLOUD_READ_TOKEN to separate service credentials; run sync_service.py with --ca-file and --devices. CI uses a disposable tenant JWT only; least-privilege service identity is Task 12.
- Mandatory development integration: genuine ThingsBoard gateway connect/telemetry QoS1 through TLS; REST pre/post verification, 72 periodic rows plus same-timestamp event, invalid field absence, original timestamps, duplicate replay and restart persistence. Existing mock/negative tests stay mandatory. Artifact thingsboard-evidence contains no credentials. Actual Wokwi acceptance remains deferred. Task 11 implements dedicated routing of sync_mode, removal of routing metadata from persisted history, and current-state/alarm semantics; until then the default ThingsBoard rule chain may store sync_mode.
