# Task 13 — Remote control and configuration

Cloud authorization remains in FarmApi (Task 12). Gateway subscribes to native ThingsBoard Gateway RPC; commands are admitted into SQLite with original UUID, creation/expiry and method. The Gateway checks expiry before each retry and sends Protobuf FPort 21 only after a valid uplink. One Class A downlink carries the command and the explicit ACK sequence of the committed uplink. With no command the bridge preserves FPort 20 ACK behavior. Wokwi's artificial UTC epoch requires translating remaining TTL at dispatch. This is not an RF measurement or production ChirpStack queue integration.

Firmware independently validates the canonical Protobuf, UTC expiry, config version and safe wind state. Valid configuration takes effect for the next aggregation boundary, battery protection still overrides configured period. Remote stop is latched and released only by local inspection button under safe conditions. Buzzer test is bounded to three logical seconds, never suppresses wind alarm. No start pump command exists. A separate 4 KiB simulated NOR configuration journal survives reset and fails closed if torn/full (85 admissions/local confirmations, no silent eviction; fresh demo requires new simulator image after exhaustion). A durable admission prevents repeating a side effect after reset; a crash before result may yield UNKNOWN. FPort 22 responses use the existing weather ring/ACK mechanics and independent sequence/CRC. Gateway accepts results only for dispatched commands on the mapped station. Cloud gets a dedicated command_<uuid-without-hyphens> string containing lifecycle, revision and confirmed snapshot. Readback is required before reporting publication complete. APPLIED means a device result, not native RPC delivery. Desired shared and applied client attributes are independent.

Run existing Edge gateway, serial bridge, and sync_service processes with the Task 12 scoped credentials. The sync service subscribes to v1/gateway/rpc, and its callback stores commands in the same SQLite file used by gateway.py. Use FarmApi POST /api/farm/stations/{station UUID}/rpc. Dashboard is Task 14. Hardware acceptance remains deferred under the repository CI policy; development evidence is native tests and actual Cloud/MQTT integration, not measured GPIO/RF.

The FarmApi command status endpoint is POST /api/farm/stations/{station UUID}/rpc_status with {"command_id":"..."}; any scoped human reader can query a known admitted command. Cloud admission is durable even before Edge receives an RPC. Missing confirmation after expiry is UNKNOWN, not success. Desired configuration versions cannot roll back or conflict at a given version. Existing Task 12 control-service role gets the narrowly scoped WRITE_ATTRIBUTES grant through an explicit migration; human roles and reader grants are unchanged. The Edge journal holds at most 32 outstanding commands per station and 4096 admissions; exhaustion fails closed. Dispatch timestamps are retained and APPLIED results must fall within an actual dispatch interval. The new remote-control scenario is mandatory at Task 17, with a serial/Protobuf verifier. It is not executed by the development gate.

Development evidence includes actual authenticated Mosquitto traffic through the running Gateway process and SerialBridge, with native C++ command execution, FPort 22 commit-before-ACK and lifecycle verification. A separate real ThingsBoard test exercises the native Gateway MQTT subscription, scoped JWT status endpoint and independent telemetry readback. These are complementary integration boundaries, not a claim that the Wokwi simulator is running in development CI.
